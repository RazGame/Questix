# Деплой Questix в облако (ROADMAP этап 4)

Сервер: VPS с уже работающим Docker (чужие контейнеры не трогаем: свой стек
живёт в compose-проекте `questix`, порты при конфликте меняются в
`docker-compose.cloud.yml`).

## Разовая настройка доступа (руками, один раз)

1. Положить SSH-ключ деплой-машины на сервер (пароль вводите сами):

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@81.90.28.28 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

2. Сменить root-пароль, если он публиковался где-либо: `passwd`.

## Деплой (с локальной машины, Git Bash)

```bash
sh deploy/deploy.sh root@81.90.28.28      # заливает код, ключи, собирает, запускает
```

Перед первым стартом на сервере заполнить `/opt/questix/.env`
(пароль Mongo; адреса API — см. `.env.cloud.example`).

## Режимы

- **IP (по умолчанию)**: фронт `http://IP`, API `http://IP:8080`, без HTTPS.
- **Домен**: в `.env` задать `DOMAIN`, `CADDYFILE=./deploy/Caddyfile.domain`,
  `VITE_API_URL=https://api.домен` + A-записи `домен` и `api.домен` → IP.
  HTTPS Caddy получит сам. После этого пересобрать: `deploy.sh` ещё раз.

### HTTPS на локальной станции

Локальная станция (`docker compose up` на ноутбуке) работает по HTTP: телефоны
заходят на `http://LAN-IP:5173`. Экран при этом не гаснет — за это отвечает
NoSleep.js со скрытым видео, которому защищённый контекст не нужен.

Если HTTPS всё же понадобится, помните: одного сертификата на фронт мало.
Фронт ищет бэкенд на том же хосте, и под `https:` он берёт порт **8443**, а не
5000 — на 5000 слушает голый HTTP, и по TLS туда не достучаться. То есть
нужен прокси, который завернёт в TLS и фронт, и бэкенд (как `Caddyfile.ip`
в облаке, только с сертификатом). Точные адреса всегда можно задать явно
через `VITE_API_URL` и `VITE_SOCKET_URL` — они важнее умолчаний.

## RS256

Ключи `secrets/jwt.key|jwt.pub` генерируются локально (`openssl genrsa`),
в git не попадают (`secrets/` в .gitignore), на сервер уезжают deploy-скриптом.
Приватный ключ живёт только в облаке; станции для проверки облачных токенов
достаточно `jwt.pub` (env `JWT_PUBLIC_KEY_FILE`). Без ключей backend работает
на HS256 (`JWT_SECRET`) — локальная станция не меняется. Старые HS256-токены
после включения RS256 перестают работать — пользователи перелогиниваются.
